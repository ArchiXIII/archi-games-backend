# Сводка проекта Archi Games Backend

## Назначение

Backend обслуживает HTML5-игры Archi Games в Yandex Cloud. Первая подключаемая игра — `crystal-match`, платформа — VK. Сервис хранит серверный баланс игроков и предоставляет основу для безопасной, транзакционной и идемпотентной обработки внутриигровых покупок.

## Технологии

- Node.js 22 и CommonJS
- Yandex Cloud Functions
- Yandex API Gateway
- YDB Serverless
- официальный Node.js SDK YDB
- встроенный тестовый фреймворк `node:test`

## Реализовано

- точка входа Cloud Function `index.handler`;
- лёгкий роутер событий Yandex API Gateway;
- единый JSON-формат ответов и ошибок;
- `X-Request-Id` и структурированные безопасные логи;
- ограничение размера тела запроса и проверка `Content-Type`;
- CORS только для разрешённых origin;
- проверка подписи VK launch parameters через HMAC и `timingSafeEqual`;
- получение серверного баланса игрока;
- allowlist безопасных полей для синхронизации;
- серверный каталог товаров `crystal-match`;
- YDB-репозитории игроков, заказов и событий покупок;
- атомарная идемпотентная выдача монет по уникальному order ID;
- повторно безопасная миграция таблиц YDB;
- production ZIP-сборка без тестов, dev-зависимостей и секретов;
- OpenAPI-спецификация API Gateway;
- тесты маршрутизации, подписи VK, каталога и повторной покупки.

## Маршруты

- `GET /health`
- `GET /v1/player/balance`
- `POST /v1/player/sync`
- `POST /v1/vk/payments/callback`

Платёжный callback пока намеренно закрыт ответом `501 VK_CALLBACK_NOT_CONFIGURED`. В проекте сохранён явный TODO со списком данных, которые нужно получить из актуальной документации и кабинета VK. Ответ клиентского VK Bridge не используется как подтверждение платежа.

## Модель данных

YDB содержит таблицы:

- `players` — серверный баланс игрока;
- `orders` — состояние и уникальность заказа платформы;
- `purchase_events` — журнал событий покупки.

Ключ заказа `(platform, platform_order_id)` и единая транзакция предотвращают повторное начисление монет.

## Проверенное состояние

- 10 тестов проходят;
- аудит npm сообщает 0 известных уязвимостей;
- production ZIP успешно создаётся;
- корень ZIP содержит `index.js`, `package.json` и `package-lock.json`;
- ZIP не содержит тесты, dev-зависимости, `.env`, ключи или секреты;
- handler из распакованного ZIP успешно отвечает на `/health`.

Собранный локальный артефакт: `dist/archi-games-api.zip`. Каталог `dist` не публикуется в Git.

## Необходимая конфигурация

- `YDB_ENDPOINT`
- `YDB_DATABASE`
- `VK_APP_ID`
- `VK_APP_SECRET`
- `VK_CALLBACK_SECRET`
- `ALLOWED_ORIGINS`
- `NODE_ENV=production`

Функция использует сервисный аккаунт и metadata service. JSON-ключ сервисного аккаунта не требуется и не должен храниться в проекте.

## Что осталось перед production-запуском

1. Получить точный server-to-server callback-контракт и параметры проверки подлинности в кабинете VK.
2. Реализовать VK-адаптер без изменения внутреннего `PurchaseService`.
3. Запустить миграцию в целевой YDB.
4. Задать переменные и секреты в версии Cloud Function.
5. Загрузить ZIP и указать entrypoint `index.handler`.
6. Подставить ID сервисного аккаунта API Gateway в OpenAPI и обновить gateway.
7. Выполнить интеграционную покупку и повтор того же callback в тестовой среде VK.

Подробные инструкции находятся в `README.md`.
